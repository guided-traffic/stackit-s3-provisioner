# Package map

Where the Go packages, the generated manifests, the chart, the test tree and the build files of this
repository live, what each is responsible for, and where the boundaries between them were drawn on
purpose. Read it when you are new, or when you are looking for the file that owns a behaviour. If you
already know which subsystem you are changing, the page that explains that subsystem is next door —
[reconcile-pipeline.md](reconcile-pipeline.md), [bucket-identity.md](bucket-identity.md),
[bucket-policy.md](bucket-policy.md), [credentials.md](credentials.md), [clone.md](clone.md),
[usage-measurement.md](usage-measurement.md), [circuit-breaker.md](circuit-breaker.md),
[provider-errors.md](provider-errors.md) or [stackit-api.md](stackit-api.md) — and if you want which
suite to run, what each costs and what CI actually executes rather than the layout, that is
[testing.md](testing.md).

This page names files and functions on purpose. That is what makes it useful and it is also what
makes it go stale: **whoever moves a file updates this page in the same change.**

## Why the provider client has two halves

StackIT Object Storage is two separate surfaces, and the operator has to speak both.

| | Control plane | Data plane |
|---|---|---|
| Protocol | STACKIT REST API via `stackit-sdk-go` | S3 via `minio-go` |
| Credential | Service-account key flow, bearer token | S3 access key + secret |
| Caller | the operator only | the operator **and** every workload |
| Owns | service enablement, buckets, credentials groups, access keys | objects, bucket tags, **bucket policies** |
| Code | [`stackit/client.go`](../../stackit/client.go), type `Client` | [`stackit/s3.go`](../../stackit/s3.go), type `S3Admin` |

The split is forced, not stylistic: **a bucket policy is an S3 operation and the control-plane SDK
has no call for it.** Verified against the pinned `services/objectstorage v1.9.1` (see
[`go.mod`](../../go.mod)): its `APIClient` exposes exactly `CreateBucket`, `DeleteBucket`,
`ListBuckets`, `GetBucket`, `CreateCredentialsGroup`, `DeleteCredentialsGroup`,
`ListCredentialsGroups`, `GetCredentialsGroup`, `CreateAccessKey`, `DeleteAccessKey`,
`ListAccessKeys`, `EnableService`, `DisableService`, `GetServiceStatus`, and the compliance-lock and
default-retention calls. There is no policy operation in the package at all — the word "policy" does
not occur in it. Isolation between workloads is nevertheless only achievable through a bucket policy
([ADR 0003](../adr/0003-workloads-are-isolated-by-an-explicit-deny-policy.md)), so the operator must
hold an S3 credential of its own to write one, which is the whole reason
[ADR 0004](../adr/0004-the-operator-bootstraps-its-own-s3-admin-credential.md) exists.

Both halves live in **one Go package**, `stackit`. `Client` and `S3Admin` are constructed
independently and share nothing but the package: verified on 2026-09-19,
[`stackit/s3.go`](../../stackit/s3.go) imports only the standard library and three `minio-go`
packages and references no package-internal identifier from `client.go`, `errors.go` or `retry.go`,
and [`stackit/errors.go`](../../stackit/errors.go) is consumed only by `client.go`. So there is no
import cycle waiting for a refactorer — the data plane is self-contained and could be split out
mechanically. The reason not to is simply that the split would buy nothing: the two halves are
configured from the same provider account, are always used together, and one package keeps that
obvious.

`docs/` holds a fifth directory that is the outstanding-work backlog rather than a documentation
home. Nothing under `docs/adr/`, `docs/developer/`, `docs/operations/` or `docs/security/` cites it,
and nothing should: an ADR is the authority for a decision, and a page explains the mechanism that
implements it. A page describes what is, never what is planned.

The `account-*.json` keys in that listing are the one thing at the root worth knowing before you
meet it: the single line in [`.gitignore`](../../.gitignore) is all that keeps a real RSA private key
out of the repository, and their custody is
[credentials-and-secrets.md](../security/credentials-and-secrets.md). One more root-level habit: the
design rationale a code comment points at lives in an ADR, and comments cite a rule by its stable
address, `ADR 0006 D2`, rather than by a section number in a document, because a section number
silently repoints when something is inserted above it.

## `stackit/` — the provider client

| File | Responsibility |
|---|---|
| [`client.go`](../../stackit/client.go) | Control-plane wrapper bound to one service account and one region. `LoadAccount` reads the key file for its `projectId`; `NewClient` builds the SDK client under the retrying transport; `EnsureService` enables Object Storage idempotently and caches the verified answer for the process lifetime; then the bucket, credentials-group and access-key calls, plus `BucketConnInfo`/`BucketEndpoint`, which derive the S3 host and the path-style URL from the bucket's own `urlPathStyle` field. |
| [`errors.go`](../../stackit/errors.go) | Error classification. `ProviderRefused` recognises the provider's own structured refusal (JSON 400/401/403); `isServiceNotEnabled` recognises a structured JSON 404. The discriminator is `json.Valid` on the body, never the status code alone, because an intermediary's HTML error page arrives as the same Go type. Explained in [provider-errors.md](provider-errors.md). |
| [`retry.go`](../../stackit/retry.go) | `retryTransport`, a `RoundTripper` that repeats **GET and HEAD only**, on transport errors and 5xx, never on 429. It sits beneath the SDK's authentication (see [the boundaries](#the-boundaries-worth-knowing)). Also shortens the idle-connection timeout on a clone of `http.DefaultTransport`. |
| [`s3.go`](../../stackit/s3.go) | Data plane. The action lists and `BuildIsolationPolicy`, which composes the two- or three-statement deny document; `PoliciesEquivalent` for drift comparison; `WorkloadPrincipalFromPolicy`, which reads a bucket's own policy back to recover the workload group it belongs to ([ADR 0002](../adr/0002-a-credentials-group-is-attributed-through-its-bucket.md)); and the `S3Admin` client with `SetBucketPolicy`, `GetBucketPolicy`, `SetBucketTags`, `BucketTags`, `WipeBucket`, `BucketStats`, `BucketUsage` and `BucketEmpty`. |

`s3.go` is the largest single concentration of security-relevant decisions in the repository: the
comments above `workloadAllowedActions`, `readerAllowedActions` and the `deniedByDesign` block record
why each action is in or out, and why the third statement is a strict read-only subset. Do not extend
either list without reading them — [bucket-policy.md](bucket-policy.md) explains the mechanism and
[ADR 0003](../adr/0003-workloads-are-isolated-by-an-explicit-deny-policy.md) the rules.

## `api/v1/` — the Bucket API

| File | Responsibility |
|---|---|
| [`bucket_types.go`](../../api/v1/bucket_types.go) | The `Bucket` CRD: spec, status, every nested type, and the kubebuilder markers that generate the CRD schema and its CEL validation. It also carries every helper that derives a value **from** a Bucket, so the derivation has exactly one implementation. |
| [`groupversion_info.go`](../../api/v1/groupversion_info.go) | Group `stackit-bucket.gtrfc.com`, version `v1`, and the scheme builder. |
| [`zz_generated.deepcopy.go`](../../api/v1/zz_generated.deepcopy.go) | Generated by `controller-gen`. Never hand-edited; regenerate with `make generate-all`. |

The helpers in `bucket_types.go` are the reason to look there first when a value seems to be computed
in two places — it is not:

| Helper | What it decides |
|---|---|
| `BucketNaming.ComposeBucketName` / `Validate` | The physical bucket name from the install-time prefix and namespace policy ([ADR 0009](../adr/0009-the-physical-bucket-name-is-composed-and-then-frozen.md)) |
| `Bucket.EffectiveBucketName` | Which cloud bucket a CR *is*: `status.resolvedBucketName` first, then the `resolved-bucket-name` annotation as the backup for a lost status, then the raw `spec.bucketName` |
| `SecretKeys.<field>Key` | The resolved key name for each field of the workload Secret, falling back to the `Default*Key` constants |
| `Bucket.SecretData` | The full `map[string][]byte` written to the workload Secret, omitting optional fields that are empty |
| `Bucket.ValidateSecretKeys` | Rejects a key collision before a write silently loses one of the two values |
| `Bucket.PendingRotationTrigger` | Whether the rotation annotation carries a value the status has not yet acknowledged |
| `CloneFrom.HoldSecret` / `VirtualHosted` / `EndpointURL` / `EndpointHost` | The clone source's defaults and address form |
| `UsageSpec.UsageEnabled` / `UsageIncludeVersions` / `UsageInterval` | The per-CR measurement request, resolved against the cluster default |

After changing anything in this directory run `make generate-all`, which regenerates the CRD and the
deepcopy code and copies the CRD into the chart. **The pull-request pipeline will not catch you if
you skip it.** Verified on 2026-09-19: the drift check — `make generate-all` followed by a failing
`git diff --quiet` — exists only in
[`.github/workflows/build.yml`](../../.github/workflows/build.yml), which triggers on
`release: published`. [`release.yml`](../../.github/workflows/release.yml), the workflow that runs on
push and pull request to `main`, runs no generate or diff step, and none of its targets (`lint`,
`gosec`, `vuln`, `cyclo`, `test-unit-coverage`, `test-integration-coverage`, `test-helm-render`,
`test-e2e`) depends on the generate targets. A stale generated CRD therefore merges green and breaks
the release.

## `cmd/` — the manager binary

[`cmd/main.go`](../../cmd/main.go) is a single `main` plus small typed environment helpers
(`envOrDefault`, `envBoolOrDefault`, `envIntOrDefault`, `envInt64OrDefault`, `envDurationOrDefault`)
and `parseUsagePrice`. Twenty-two of the twenty-five flags carry an environment-variable fallback, so
the chart can pass whichever is more convenient; the exceptions are `--metrics-bind-address`,
`--health-probe-bind-address` and `--leader-elect`, which take literal defaults only. One setting
runs the other way and has no flag at all: the clone Job's pod resources are read from
`CLONE_JOB_RESOURCES` as JSON, which is how the chart passes `clone.resources` through. What `main`
decides, in order:

1. Parses flags, then validates the naming policy — an invalid `--bucket-name-prefix` exits at
   startup rather than producing unusable bucket names later.
2. Parses `--bucket-usage-price-per-gb-hour` as a string, so a typo exits with a message instead of
   silently costing zero.
3. Builds the manager with leader election optional and `LeaderElectionReleaseOnCancel` set, so a
   rolling update hands over in seconds instead of waiting out the lease.
4. Builds the `stackit.Client` **only if** `--stackit-sa-key-path` is set. Without a key the operator
   runs in skeleton mode and makes no cloud call at all
   ([ADR 0005](../adr/0005-the-operator-serves-one-project-in-one-region.md)). With a key it also
   insists on knowing its own namespace, because the admin credential has to be persisted somewhere.
5. Wires `BucketReconciler` and `BucketUsageReconciler` into the same manager, sharing one
   `stackit.Client` and one admin-Secret location. They do **not** share the circuit breaker: the
   `ProviderBreaker` built here is passed to `BucketReconciler` and to `RegisterBucketMetrics` only,
   and `BucketUsageReconciler` has no breaker field at all
   ([`bucket_usage_controller.go`](../../internal/controller/bucket_usage_controller.go)).
   Measurement keeps running while the circuit is open, which is consistent with
   [ADR 0014](../adr/0014-bucket-size-is-measured-by-a-separate-controller.md) D3 — a measurement
   failure is informational and must not inflate the provisioning error signal — and worth knowing
   before you read a measurement failure during an outage as a bug.
6. Registers the metrics collector, the health and readiness probes, and starts.

`--enable-wipe-on-delete` and `--bucket-usage-enabled` are the two operator-wide gates: the CR field
is a request, the flag is the permission
([ADR 0006](../adr/0006-a-bucket-is-deleted-only-when-it-is-empty.md),
[ADR 0014](../adr/0014-bucket-size-is-measured-by-a-separate-controller.md)). The settings whose
consequences are not obvious are explained in [configuration.md](../operations/configuration.md).

`internal/` rather than a public package is deliberate: nothing here is an API for anyone else, and
keeping it unimportable keeps the CRD types the only supported surface.

## `internal/stackitfake/` — the in-memory provider

[`fake.go`](../../internal/stackitfake/fake.go) serves **both** provider surfaces from one shared
state over two `httptest` servers: `Server.CP` speaks the control-plane REST API the SDK expects, and
`Server.S3` speaks enough S3 XML for `minio-go`. Because the state is shared, a bucket created through
the control plane is immediately taggable and policy-able through the data plane, exactly as in the
real service.

Its fidelity notes are the point of it — each one mirrors a behaviour verified against the live API:

| Situation | Fake answers | Why it matters |
|---|---|---|
| A foreign `projectId` | 403 | cross-project isolation ([ADR 0005](../adr/0005-the-operator-serves-one-project-in-one-region.md)) |
| Creating a bucket that exists | 409 | the adoption path has to distinguish this from a failure |
| Deleting a non-empty bucket | 409 | the empty-only delete guard ([ADR 0006](../adr/0006-a-bucket-is-deleted-only-when-it-is-empty.md)) |
| Deleting a group that still has keys | 422 | fixes the teardown order: keys before groups |
| Deleting an access key without the group parameter | 500 | the trap that makes the group id a required argument |
| Reading tags or policy that were never set | `NoSuchTagSet` / `NoSuchBucketPolicy` | "absent" must not read as "failed" |

Beyond the happy paths it offers the seams the error tests need: `FailNext` arms one structured
failure, `FailNextRaw` arms an intermediary-style response (an HTML gateway page, say) that the API
itself would never produce, `OmitFromNextListing` reproduces listing lag, and `Calls` counts requests
per operation so a test can assert that the operator did *not* call something.

## `hack/` and `test/`

[`hack/e2ecleanup/main.go`](../../hack/e2ecleanup/main.go) is the sweep behind `make
e2e-stackit-sweep`. It finds buckets and credentials groups whose names carry the e2e prefix and, with
`-admin`, also drains and removes the `operator-admin` group. That last flag is why it exists at all:
the bootstrap group and its key live in the cloud while the only copy of the secret lives in a Secret
inside the Kind cluster, so deleting the cluster orphans a fully privileged, still-valid S3 key. Never
point it with `-admin` at a project that also hosts a real operator deployment.

The test tree, with the build tag each suite hides behind:

| Path | Tag | What it proves |
|---|---|---|
| [`test/integration/`](../../test/integration/) | `integration` | envtest against a real API server: CRD acceptance, CEL validation, the skeleton reconcile flow, finalizer release |
| [`test/e2e/e2e_test.go`](../../test/e2e/e2e_test.go) | `e2e` | Kind smoke test in skeleton mode — operator healthy, CR reconciled, no cloud call |
| [`test/e2e/cloud_test.go`](../../test/e2e/cloud_test.go) | `e2e` + `E2E_STACKIT=1` | the whole chain against the real provider: provisioning, read grants, measurement, a real rclone clone |
| [`test/e2e/rbac_test.go`](../../test/e2e/rbac_test.go) | `e2e` | that the chart's fragments really aggregate into built-in `view`/`edit`, by SubjectAccessReview |
| [`test/helm/render_test.go`](../../test/helm/render_test.go) | `helm` | `helm template` assertions on the user-facing roles, including the non-default values the Kind install never exercises |

Offline tests carry no build tag and live next to the code they cover, so `go test ./...` is the
complete net-free suite. Which suite to run when, and what each costs, is [testing.md](testing.md).

## The boundaries worth knowing

**The retry transport sits beneath the SDK's authentication, and that is load-bearing.** The SDK
does not retry — `config.WithMaxRetries` has been a no-op since core v0.26.0 — so one dropped
connection would otherwise be a failed reconcile. `config.WithHTTPClient` is adopted by the SDK's
auth setup as the *inner* transport, which means a `RoundTripper` installed there covers both API
requests and token fetches and runs with the `Authorization` header already attached. The exclusions
are deliberate: only GET and HEAD, because repeating `CreateAccessKey` would mint a second key whose
secret is returned once and then lost; not 429, because the one status that means "you are sending
too much" is the one where repeating makes it worse. Backing off from a 429 is the workqueue's and the
breaker's job, which act on the fleet rather than on one in-flight request.

**The fake exists so the offline suite can exercise whole flows, not mocked ones.** The alternative —
interfaces over the client with generated mocks — would have made every test assert on calls the
operator makes rather than on the state it reaches, and the expensive defects here have all been
state defects: a group adopted by the wrong bucket, a key deleted before its replacement was stored,
a policy rewritten byte-differently on upgrade. The fake also holds the *misbehaviours*, so the paths
that only exist because the real API behaves oddly stay covered offline. Its one deliberate omission
is retries: `NewClientWithEndpoint`, which tests use, installs no retrying transport, because a retry
would consume a `FailNext` injection and quietly turn an error-path test into a happy-path test.

**Measurement is a separate controller because it is unbounded and merely informational.** Listing a
bucket end to end takes as long as the bucket is large; doing it inside the provisioning reconcile
would put an unbounded operation in front of credential and policy management. With its own workqueue
and concurrency limit, a slow measurement delays at most other measurements. The write direction is
guarded in both directions: the usage controller only ever merge-patches `status.usage`, so it cannot
clobber the provisioning reconciler's fields, and the provisioning reconciler writes status with an
`Update` carrying a `resourceVersion`, so a measurement landing in between makes that update conflict
and retry rather than silently disappear. It also **reads** the admin Secret and never creates it:
minting cloud credentials is the provisioning reconciler's job, and a measurement must not be able to
do it as a side effect ([ADR 0014](../adr/0014-bucket-size-is-measured-by-a-separate-controller.md)).

**The breaker is its own file because it is fleet-wide state with no Kubernetes in it.** It has one
instance per process, constructed in `main`, held by the provisioning reconciler and read by the
metrics collector — the measurement controller is not wired to it at all — and its whole interface is
`Allow`, `Failure`, `Success` and `OpenedAt`. Keeping it free of controller-runtime types is what lets its
cooldown arithmetic be tested exactly, on a manually advanced clock, instead of being slept through.
The discriminator it uses is deliberately *not* a classification of the error — it is the absence of
any successful reconcile, which keeps the breaker out of error parsing entirely
([ADR 0013](../adr/0013-a-provider-outage-is-held-fleet-wide.md)). Error classification is a separate
concern and lives in [`stackit/errors.go`](../../stackit/errors.go) and the `degrade`/
`holdsReadyThrough` helpers ([ADR 0012](../adr/0012-ready-describes-the-last-verified-state.md)).

**The CRD has one source and two copies.** `config/crd/bases/` is generated from the markers in
`api/v1`; `make sync-helm-crd` copies it into the chart and stamps `helm.sh/resource-policy: keep` on
it. Both are generated artifacts; editing either by hand is undone by the next `make generate-all`.

## What is wrong today

**A doc comment in `api/v1` is published twice, and you will not notice.** Every comment on a field
of [`api/v1/bucket_types.go`](../../api/v1/bucket_types.go) is copied verbatim by `controller-gen`
into [`config/crd/bases/stackit-bucket.gtrfc.com_buckets.yaml`](../../config/crd/bases/stackit-bucket.gtrfc.com_buckets.yaml)
and from there into [`templates/crd.yaml`](../../deploy/helm/stackit-s3-provisioner/templates/crd.yaml),
so it ends up in `kubectl explain` on every cluster that installs the chart. Write those comments for
a cluster operator, not for a reviewer, and remember that changing one is a CRD change: it needs
`make generate-all` and it ships a chart version.

**A stale generated CRD merges green.** The `make generate-all` drift check runs only in the release
workflow, on `release: published`; the pull-request pipeline has no generate or diff step at all, and
none of its make targets pulls one in. Forgetting `make generate-all` after an `api/v1` change is
therefore caught at release time, by the person cutting the release, rather than at review time by
the person who made the change.

**The kustomize path cannot provision.** [`config/manager/manager.yaml`](../../config/manager/manager.yaml)
passes only `--metrics-bind-address` and `--health-probe-bind-address` and mounts no service-account
key, so `make deploy` produces a skeleton-mode operator. It is useful for checking that the manifests
apply and for nothing else. The chart is the only install path that provisions.

**Nothing syncs the operator's RBAC into the chart.** `make manifests` regenerates
[`config/rbac/role.yaml`](../../config/rbac/role.yaml) from the `+kubebuilder:rbac` markers, but
`make sync-helm-crd` copies only the CRD. The chart's
[`clusterrole.yaml`](../../deploy/helm/stackit-s3-provisioner/templates/clusterrole.yaml) is
hand-written and must be edited in the same change as any marker. Verified on 2026-09-19: the two
currently agree on every rule, except that the generated role has no `leases` rule at all — leader
election has no kubebuilder marker, and the chart adds that rule itself when
`leaderElection.enabled` is on. A kustomize deployment with `--leader-elect` would therefore lack the
permission, which is a second reason not to use that path.

**`bucket_controller.go` is about two thousand lines** and holds the provisioning pipeline, ownership,
attribution, grants, credentials, teardown, the watches and the error-outcome helpers. Nothing is
misplaced — every part of it reads or writes the same Bucket within one pass — but it is the file
where a reader is most likely to miss a caller. [reconcile-pipeline.md](reconcile-pipeline.md) is the
map through it.
